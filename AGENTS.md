# Anzuki maintenance

- ARTWORK IS THE HIGHEST PRIORITY. Preserve the original pixel resolution, frame rate and opaque character colors. Never downscale source assets, apply lossy re-encoding, convert RGBA to subsampled YUV, or trade visual quality for smaller downloads without explicit user approval.
- The canonical playback format is original-size 720×1280 lossless RGBA animated WebP. Verify decoded pixels against every keyed frame. Desktop and Android must use byte-identical assets; display sizing is not permission to reduce file resolution.

- Click speed is 1.0–2.0 in 0.1 increments, applied on the next click. Desktop clicks use predecoded original-resolution bitmaps and a monotonic frame clock; Android retimes WebP ANMF duration metadata in memory. Never transcode or interpolate artwork frames. Every click restarts the click animation immediately, even while another click is playing. Keep long/short idle choices and range definitions synchronized via the shared playback config and index.
- Voice uses user-provided recordings, imported byte-for-byte. Never synthesize or replace their voice without instruction. Keep `pet/voice-config.json` and `pet/voice-lines.json` identical in Android assets. User clarification: AUDIO FILES ONLY. Accept freely named audio, never video imports or video-audio extraction. Filter the picker to audio and validate content has decodable audio and no video track, including renamed videos. Preserve prior imported files but exclude known video files from playback; never delete personal files as part of an update. Copy bytes, never transcode. Give each clip editable dayType (all/weekday/holiday) and period filters. Weekday means Monday–Friday, holiday means Saturday–Sunday; do not infer statutory holidays. Preserve legacy recordings and their original exact restrictions until the user explicitly applies new filters. Context selection uses device-local time; never substitute a wrong weekday/time line. Manual preview may bypass schedule, never mute. Animation speed must not change audio playback speed. Personal imported audio remains local.
- For existing Windows users, deliver only the necessary incremental update ZIP (`Anzuki-Windows-Update`) by default. Compare against the prior successful Windows bundle, include changed files plus the small shared code/config dependencies required by the current ASAR (users may skip code-only updates), apply the patch to that bundle and smoke-test it. Never include unchanged Electron runtime, artwork, personal settings or recordings in update ZIPs. Full bundles remain for first installs. Do not send an unchanged Android APK as an update.
- Keep the standalone Windows x64 artifact up to date via the read-only `Windows desktop release` workflow. Package original files unchanged; verify every resource hash and smoke-test the actual packaged EXE on Windows. Packaged settings/recordings live under `%APPDATA%/Anzuki/desktop`, outside the installation folder.
- Maintain both the desktop pet and native Android overlay app. The user asked that future changes stay synchronized.
- `pet/anzuki-config.json`, `pet/animations.json`, and `pet/anzuki-animation/*.webp` are the shared animation source of truth. Never maintain a second independent phone animation selection. Old WebM files are deprecated historical compatibility assets and must not become the default player.
- After desktop animation changes, regenerate Android assets with `scripts/sync-android-assets.py`, build `android/releases/Anzuki-Android.apk`, and run `scripts/check-platform-sync.py`. `scripts/update-all.py --sdk <sdk>` performs the full source-video pipeline and Android build.
- Release packaging reuses exact artwork bytes and stored signed-APK metadata in `android/releases/packaging/`; `node scripts/restore-android-release.mjs` must reproduce the expected SHA-256. Publish signed APKs through the read-only `Signed Android release` workflow artifact. Do not add workflows with repository write permissions. Preserve previous APKs in history/archive.
- Keep the existing development signing key under `.local/android-signing/` for compatible APK updates. Never commit signing keys, keystores, build caches, runtime data, or credentials.
- Retain original uploaded media and processed outputs when the user supplies new source footage. Keep prior character references for comparison.
- The user has authorized publishing Anzuki reference revisions, prompts, source changes and uploads to the public `JackeyUi/AnzukiDest` repository until revoked. Do not upload to Google Drive unless separately requested.
- Report validation accurately: successful compilation and APK signature checks do not establish successful interaction on a physical Android device.
